# Agent-readable CI logs: a server-credentialed proxy of Forgejo's web log route, redacted, advertised at the point of need

ADR-0032 gave an agent `labctl pr checks` and deferred the logs behind the red rows, betting that a failing check's name was enough to reproduce the failure locally. It wasn't: agents that see red but not why work around the gap — guessing at the failure, re-pushing blind, or skipping validation outright. This ADR closes 0032's deferral: the `Tracker` seam grows `CheckLog(ctx, number, name) ([]byte, error)`, reachable as `labctl pr logs <n> [--check <context>]` over the run-token agent surface (ADR-0014), so the fix-the-red loop's diagnose leg runs on the actual failure text instead of a job name.

Forgejo's REST API (15.0.5, verified against this instance's swagger) has no job-log endpoint — `/actions/runs` and `/actions/tasks` exist, job logs don't. So lab proxies the undocumented web route the UI's "Download logs" button uses: the commit-status rows `Checks()` already decodes carry a `target_url` of exactly `/{owner}/{repo}/actions/runs/{run}/jobs/{job}`, and `GET {target_url}/attempt/{k}/logs` answers `200 text/plain` with the full plaintext log. That join — `target_url` to log route — is the whole adapter, and it is deliberately version-coupled to Forgejo internals.

The pins, decided:

- **Version-coupling is loud, never silent.** Any answer outside the adapter's expected shape — a non-200/404 status, a 200 that isn't `text/plain` (a login page), a 404 on attempt 1, a `target_url` that stops matching the Actions job shape — wraps a new sentinel `tracker.ErrLogAdapterMismatch` whose message says what was asked, what came back, and what to do ("file an issue on coding-lab, then debug from local repro"). An agent must always be able to tell "no logs exist" from "lab is broken"; empty output with exit 0 is the one forbidden outcome.
- **Latest attempt by probing.** A rerun bumps the attempt counter and the run page links attempt 1, so the adapter probes `attempt/1, 2, …` until the first 404 and serves the last 200 (capped; the cap is a mismatch error). Attempts above 1 are rare, so the extra requests are noise.
- **The server's forge credential rides the log request** even though the route answers anonymously on public repos today — a private repo must fail loudly at the adapter seam, not silently once the repo flips private. Session-cookie machinery is explicitly out of this slice.
- **`CheckLog` is a primitive; selection is policy, held server-side.** The tracker method fetches one named check's log, any state — a still-running job yields the partial log so far. Which checks to fetch (default: the failing subset of the same `Checks()` read; `?check=` names one) is decided in the agentapi handler, mirroring 0032's lab-side aggregate: backends fetch, lab decides. A check whose `target_url` doesn't point at a Forgejo Actions job (external CI posting statuses) wraps `ErrUnsupported` — truthful "this forge does not serve that check's logs", not an adapter bug. The GitHub backend defers to a future slice (`ErrUnsupported`); builtin's `CheckLog` refuses the same way but is unreachable through the handler, since builtin's zero-row `Checks` means default mode answers "no failing checks" first (0032's truthful-empty stance).
- **Wire**: `GET /agent/v1/prs/{n}/logs[?check=<context>]`, run-token scoped like every agent read. `200 text/plain` carries the logs — default mode separates sections with a `=== logs: <name> ===` header line, `?check=` dumps that one log bare; `204` is default mode finding no failing checks; `404` for an unknown context carries the available context names in the error body; `409` unsupported, `502` adapter mismatch, `503` rate-limited. All logs are fetched and buffered before the first body byte, so every failure is a real status code, never a truncated 200.
- **Redaction ships in this slice — no unredacted version ever exists.** The response body passes through the `internal/secrets` derived-forms redactor (`secret exec`'s kernel): every lab-vault secret value for the repo, in every derived encoding, becomes `[REDACTED:NAME]` before a byte leaves the server. Fail-closed: a redactor that cannot be built (store or vault error) is a 500, never a raw-log fallback. Forgejo masks its own Actions secrets; this is defense in depth for lab-managed values that leak into CI output some other way.
- **CLI**: `labctl pr logs <n>` dumps the raw full logs of every failing check to stdout; no server-side truncation exists to design or get wrong — agents pipe through `tail`/`grep` themselves. `--check <context>` fetches one check by the context name `pr checks` prints, green or pending included. Exit codes follow the binary-wide convention (not `pr checks`' deliberate override): `0` logs printed · `1` nothing to print (no failing checks, or unknown context with the available contexts on stderr) or transport/API error · `2` usage.
- **Advertised at the point of need**, because the feature exists to change behavior: a red `pr checks` report (single-shot or `--wait`'s red exit) appends `logs: labctl pr logs <n>` to stderr — stderr, because 0032 pinned stdout as the parseable row surface; the seeder's CLAUDE.local.md usage table documents the verb; the AFK lander and fix prompts prescribe fetching logs as the first move on red checks, before local repro or re-push.

## Status

Accepted. Closes the deferral ADR-0032 named as its natural successor, and extends ADR-0014's run-token surface and ADR-0024's `labctl pr` family (`logs` joins `create | view | list | merge | checks`). Applies the fail-closed redaction stance of the `internal/secrets` seam. The adapter, handler, and verb are each fixture-tested where they live; the mismatch error path is tested as deliberately as the happy path.

## Considered options

- **Wait for a Forgejo REST log endpoint instead of proxying the web route.** Rejected: no such endpoint exists in the deployed version, and the gap is hurting agent behavior now. The web route is undocumented, so the adapter treats every unexpected response as a loud, actionable mismatch rather than pretending the coupling is stable.
- **Server-side truncation or size limits on the log body.** Rejected: any cap lab picks is wrong for someone — a grep needs the whole file, a tail needs the end. Raw full logs with client-side piping has no parameter to mis-tune.
- **A streaming `CheckLog` (`io.ReadCloser`) through tracker and handler.** Rejected: buffering keeps the error contract honest (a fetch failure becomes a status code, not a torn 200) and the interface shape simple; CI logs are megabytes, not gigabytes.
- **Selection policy (which checks) inside each backend.** Rejected: it would be re-implemented per forge and drift; the handler already holds the `Checks()` rows and the normalized states, so the failing-subset default lives once, server-side — the 0032 pattern.
- **Session-cookie auth for private repos if token auth is refused by the web route.** Rejected for this slice: the token is sent, and a refusal surfaces as the adapter's loud error. Cookie machinery is its own decision if the need materializes.
- **Ship unredacted first, redact later.** Rejected outright: the redaction pass is in this slice's definition of done, fail-closed, because a log endpoint that leaks vault values even once poisons the well.
