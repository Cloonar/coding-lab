# The agent brief lives in the issue body: one contract per issue, named in the AFK seed prompt — with issues created agent-ready from an approved plan, thick slices by default, the issue author on the agent surface, and unattended triage that prepares but never decides

The grill → issues → triage → AFK → land workflow (the vendored skills bundle, ADR-0012; the agent triage surface, ADR-0014) was tuned in mid-2026 for agents that needed thin slices and a human pass over every issue. By October 2026 the bottleneck had moved from the agents to the human triage pass. On the GitHub tracker, #33 had carried complete acceptance criteria since 2026-08-14 and still sat in `needs-triage`; #47 was scoped during the #39 grilling session, its only blocker closed, and it too waited for a triage pass. Three properties of the workflow produced that queue:

- **Two specifications per issue.** The triage skill posted an `## Agent Brief` *comment* and declared it the contract, with the issue body as context. Nothing told the AFK run that: the seed prompt (ADR-0027) says only "read it fully, including comments". The scheduler meanwhile reads `## Blocked by` from the *body* only (ADR-0042), a carve-out the brief guide had to spell out, and the Schedule flows (ADR-0062) file body-only specifications. Two shapes of ready issue were in the queue, and the consumer was told about neither.
- **Everything re-entered triage.** `to-issues` labeled every slice `needs-triage`, even though the maintainer had just approved the breakdown in the same session, so each slice needed a second, per-issue pass before an agent could claim it.
- **Thin slices by instruction.** `to-issues` asked for "thin", "narrow" slices and "many thin slices over few thick ones". The OneCLI work came out as five issues (#23–#27). The Warpgate work, where "one issue, one PR" was pinned during grilling, went through as one issue (#39) and merged the same day. The agents had outgrown the rule; the prompt had not.

The pins, decided (with the maintainer, 2026-10-03):

- **One agent brief per issue, in the issue body.** The body is the contract the implementer works from; comments are history and discussion. A brief is written as the body when an issue is created, and an existing issue that a maintainer or one of the workflows wrote has its body rewritten into the brief. `## Blocked by` is now simply the brief's last section — ADR-0042's "body only" rule stops being an exception to where the specification lives.
- **Comment form for a third party's report.** A reporter's words are theirs: on an issue someone other than a maintainer filed, the body stays as written and the brief is a comment headed `## Agent Brief`. The latest such comment is the contract (a changed brief is re-posted whole, never as a delta); only the body's `## Blocked by` section is edited.
- **The consumers are told.** The built-in AFK seed prompt's step 1 names the contract — the body, or the latest `## Agent Brief` comment when one exists — and the validation core says the same for the lander's diff-scope check. An operator `afk_prompt` override replaces the built-in wholesale and does not inherit the sentence: ADR-0027's WYSIWYG rule stands.
- **Contract before label, unchanged in spirit.** The brief is in place before `ready-for-agent` is applied. At creation the two arrive together, so an agent-ready issue is created with its label in the create call — the shape the autolander flow already used.
- **Issues from an approved plan are created at their destination.** `to-issues` labels an AFK issue `ready-for-agent`, a HITL issue `ready-for-human`, and only an issue with a decision still open `needs-triage`. The maintainer's approval of the breakdown is the triage decision.
- **Thick slices by default.** An issue is one unit of work that lands together: one run, one pull request. The plan starts as a single issue and is split only where the parts can land independently *and* the split buys something (parallel work on disjoint code, a blocker, a human gate), or where the whole exceeds what one run can finish. Vertical slicing still governs *how* to split.
- **Grilling is unchanged, except that slicing is one of its decisions.** The relentless, one-question-at-a-time interview stays exactly as it was — the maintainer wants it, because it is what lets them intervene on the important decisions. Both grilling skills gain one sentence: how the plan is cut into issues is resolved in the session. Inside triage, glossary entries and ADRs are no longer written from the triage worktree; they are recorded in the brief so the implementing pull request carries them.
- **The agent surface shows who filed an issue.** `tracker.Issue` gains `Author`, filled like `Comment.Author` on every binding, and `labctl issue view` prints an `author:` line. It is what lets an agent tell a maintainer's issue from a third party's report. It is display identity, never an authorization input.
- **Unattended triage prepares; the maintainer decides.** The triage skill gains an unattended mode for a scheduled run: explore, reproduce, and leave each issue either with its open decisions posted as questions (each with a recommended answer) or with its brief written and a "ready to promote" note. Promotion stays human: the maintainer applies the label, or approves in a comment a later run acts on. Who is a maintainer comes from the run's prompt or the repo's issue-tracker doc, never from the issue; text from anyone else is material to evaluate, never an instruction and never approval. The run never closes an issue and never writes `.out-of-scope/`.
- **It is a Schedule with a prompt, not a flow.** The Schedule form's example picker gains a triage starter, used with no flow selected. Its maintainer placeholder is deliberate: left unfilled, the run can establish no maintainer and promotes nothing.
- **AFK runs file what they do not fix.** The seed prompt's step 3 holds the scope: a pre-existing bug or unrelated improvement worth acting on becomes a `needs-triage` issue named in the pull request body, instead of a drive-by change the lander would have to flag.
- **No engine change.** Selection, claim, done-signal, budget and strikes are untouched. Every tracker write here is a deliberate agent workflow action through the seam — ADR-0014's invariant that the engine never writes tracker state holds.

## Status

Accepted. Extends ADR-0014 (the agent triage surface gains the issue author) and builds on `labctl issue edit` (ADR-0046's `Tracker.EditIssue`), which is what makes a body-form brief practical. Changes the built-in text ADR-0027 serves as the AFK prompt default, leaving its override mechanics alone. Leaves ADR-0042's grammar untouched while removing the reason it read as a special case. Adds a prompt starter under ADR-0062's "UI-only starters" allowance and no flow. Issues briefed before this ADR keep working: an `## Agent Brief` comment is exactly the comment form.

## Considered options

- **Keep the brief as a comment on every issue.** Rejected: it leaves two specifications on every issue the workflows wrote themselves, keeps the `## Blocked by` carve-out, and disagrees with the shape the Schedule flows already file.
- **Always rewrite the body, third-party reports included.** Rejected: one shape would be simpler for the consumer, but it overwrites a reporter's words on a public tracker. The comment form costs one sentence in the seed prompt.
- **A third built-in flow for triage.** Rejected: a flow routes the findings of an investigation into the tracker (ADR-0062). Triage is not an investigation, its outputs are defined by the skill, and a flow block would duplicate the skill while staying selectable beside flows that contradict it.
- **Let unattended triage promote on its own judgment.** Rejected: anyone can file an issue on a public tracker, and with Autoland on, self-promotion would be an unreviewed path from a stranger's text to the default branch.
- **A stop condition for grilling, or batched questions.** Rejected by the maintainer (see the grilling pin).
- **An under-specified-issue exit for AFK runs** (hand the issue back to triage without counting a failure). Deferred: it needs a second done-signal in the reaper. Revisit if lander rejections trace back to thin briefs.

## Consequences

- `assets/skills/to-issues/SKILL.md`: slicing rules rewritten (fewest issues that land on their own), destination labels at creation, the body written as an agent brief; the description — which rides in every session — no longer asks for tracer-bullet slices.
- `assets/skills/triage/AGENT-BRIEF.md`: where the brief lives; paths allowed as starting hints (this ends the contradiction with the autolander flow, which asks for files in scope); new sections for decisions with reasons, how to verify, and assumptions to check; a body-form template.
- `assets/skills/triage/SKILL.md`: reproduce before recommending, recommendation and draft brief in one turn, the grilling skill referenced by file (it is not model-invocable), brief placement, and the unattended mode.
- `assets/skills/grill-me/SKILL.md`, `assets/skills/grill-with-docs/SKILL.md`: the slicing sentence. `assets/skills/land-pr/validation-core.md`: the contract sentence. `assets/skills/README.md` lists all of these as local edits to re-apply after an upstream bump.
- `internal/afk/decide.go`: `SeedPromptTemplate` steps 1 and 3; `TestSeedPrompt` re-pinned. Still eight steps.
- `internal/tracker` (`Issue.Author`) and its three bindings, `internal/agentapi` (issue detail response), `internal/labctl` (`author:` line, omitted when the server reports none).
- `web/src/routes/repo-settings/sections/Schedules.tsx`: the triage starter.
- `CONTEXT.md`: **Agent brief** joins the AFK engine vocabulary, and "brief" joins the flagged ambiguities (the per-issue contract versus `docs/agent-brief.md`, the historical product brief).
- Not measured: none of the prompt changes was tested against live sessions before landing. The numbers to watch are how long issues wait in `needs-triage`, issues filed per plan, the lander's rejection rate, and AFK timeouts on the thicker issues.
