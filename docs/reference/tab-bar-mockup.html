Tab bar

Four destinations in a bottom bar on the phone: Runs, New, Repos, More. Runs is the launch screen. The hamburger, the drawer and the drag gesture are gone. On desktop the rail stays, and its run list becomes the same component the phone shows as a page.

Everything in the frame is clickable. The toolbar picks the frame and the state, and the URL hash does the same (#phone.chat, #desktop.runs), which is how to screenshot a state headlessly. Sample runs are invented; the issue titles are the repo's real open issues.

Changed since round 1
  • The desktop frame now mirrors the shipped app (rail anatomy, chat header with back, meter, open, Stop and the ••• menu, 760px column, dock). Round 1's desktop frame was broken by a layout bug and did not represent anything.
  • History moves out of More and onto the Runs tab as a Live / Ended switch. Ended runs are runs; the switch keeps History's own URL.
  • One route map for every width. / is Runs on the phone and on desktop, where it is a proper table. The composer gets its own URL, /new.
  • The rules are written down: when the bar hides, what Back does, what re-tapping a tab does, what each badge means.

Phone

1

Runs is the launch screen. Needs you, Working, Idle, in the rail's order today, as a page with 56px rows. The brand and the live dot sit in its header, which is the only place the brand appears on a phone. A Live / Ended switch at the top is History: same page shape, grouped by day, with the outcome chip the row earned. Try: Ended, then a row, then the back arrow.

2

The Runs badge is the attention count. It counts live runs in needs-input or question state, from the shell's existing instances list. It shows on every tab page, so you can be deep in a repo's settings and still see "2". The dot on More appears only for one thing: the agent provider is logged out. Try: More, logged out.

3

New is the composer page, unchanged. Repo pills, the Issues card with Auto, the docked composer with model, effort and ···. It gets a header so it is a page like the others, and it moves from / to /new. The accent circle marks it as the one tab that creates something.

4

More holds four rows and the account. Credentials, Tokens, Settings, Install app, then who you are, the live dot and Log out. Each row carries one line of state (logged in, 2 active, the Runner), so More is also a glance at the setup. Settings keeps its category index one level below. Try: More, then Settings, then back.

5

The chat hides the bar. The bottom edge belongs to the dock (ADR-0072). The chat keeps today's header: back, two-line title, meter, •••. Back returns to the page you came from (Runs, a repo's Overview, Ended), and to Runs when the chat was opened cold from a deep link. Try: Repo home, then a live run, then back.

6

Sub-pages keep their tab lit. Repo home, issue detail, a settings category: the top bar gets a back chevron and the bar below still shows which section you are in. Re-tapping the lit tab returns to that section's root and scrolls it to the top. Try: Repo home, then tap Repos.

Tab bar anatomy

49px + safe-area-inset-bottom 4 × 25% · 44px hit areas
24px icon · 11px label · active = --link, stroke 2.3
  • Where it showsEvery authenticated page below 1024px except the Chat (/runs/:id) and the Schedule editor, which are immersive and own their back control. At 1024px the rail replaces it, as the drawer does today.
  • Runs badgeCount of live runs in needs-input or question state. Hidden at zero. Same data as the rail's dots: the shell's listInstances resource, patched by run.messages.changed, never a second fetch.
  • More dotOnly when the agent provider is logged out. It is the one setup fault that silently breaks every new run, and it is fixed on a page under More.
  • Active tabDerived from the path prefix: /, /history → Runs; /new → New; /repos… → Repos; /credentials, /tokens, /settings… → More. Sub-pages keep their section's tab lit.
  • Re-tapTapping the lit tab navigates to the section root and scrolls to the top. Tapping it on the root only scrolls.
  • BackThe chat's back arrow pops the in-app history and falls back to / when the chat is the first entry (deep link, PWA shortcut, notification). Sub-pages use the top-bar chevron to their parent, as today. The OS back gesture stays the browser's.
  • KeyboardWhen the on-screen keyboard is up, the bar is below it and out of reach anyway; nothing special is done. The composer page's docked input is already above the bar.
  • Safe areapadding-bottom: env(safe-area-inset-bottom), translucent card background with blur, 1px top border. The page below scrolls under it with matching bottom padding.
  • Gestures retiredThe follow-finger drawer drag and its state machine go. No hot zones, no scrim. Every destination is a visible control.
  • PWAManifest start_url is / (Runs). Shortcuts: New run (/new), Repos. The app badge API, where available, mirrors the Runs count.

Trade-offs

Does well

  • No learning curve. Every destination is visible, named and in thumb reach.
  • One tap from launch to the run that needs you; the count is visible from every page.
  • Phone and desktop share one route map and one RunList component. The rail is not a special case any more.
  • The composer, Repos, repo home, the chat and settings keep their current designs. Only the frame changes.

Costs

  • About 80px of bottom chrome on every list page on the phone. Not in the chat.
  • Chat to another chat is still two taps: back, then a row. The list is visible during the switch, so it is a better two taps, but not one.
  • Desktop lands on Runs instead of the composer. One extra click to start typing on a desktop, in exchange for a page that shows every run at once.
  • Credentials and Tokens sink one level. They are set-once pages, and More shows their state inline, so this should rarely matter.

What moves in code

  • AppShell.tsx: the top strip, drawer, scrim and lib/drawerGesture.ts are replaced by a TabBar below 1024px. The rail path and the instances resource stay as they are.
  • SideNav.tsx splits: a RunList component (grouped rows) used by the rail and by the new routes/Runs.tsx page; the rail keeps brand, New run, links and foot.
  • index.tsx: / → Runs, /new → the composer, /more on the phone. History.tsx becomes the Ended view of Runs.
  • ChatHeader.tsx: back pops history with a / fallback. document.title gains the count.
  • No API change. No migration.

Open questions to settle next

  • Desktop landing page. This revision makes / the Runs table at every width. The alternative is to keep the composer as the desktop landing page and have / redirect by width, which keeps today's desktop habit but makes deep links behave differently per device. I would not do that; say so if you disagree.
  • Tab memory. iOS tabs remember their stack: Repos → coding-lab → Issues, tap Runs, tap Repos, you are back on Issues. The mockup's rule is simpler (re-tap goes to the root). Memory is a small in-memory map of last path per tab; worth it if you move between a repo's issues and runs a lot.
  • History on the Runs tab. The Live / Ended switch is the one grouping change from round 1. If you would rather keep History as a row under More, nothing else moves.
  • Fourth tab name. "More" is honest but says nothing. "Settings" would be truthful once History leaves, with Credentials and Tokens as its first rows, and the logged-out dot reads better on a tab called Settings.
  • Runs row content. The rows show state phrase, AFK budget and the behind chip. A one-line preview of the agent's last message (direction B's idea) would need the API to expose it; it can be added later without changing the frame.
  • Tablet widths. 640 to 1023px keeps the tab bar. A 10-inch tablet in landscape could carry the rail instead; the breakpoint is one number.
