What changed after the round-1 review

phone first

Same shape: the composer docks at the bottom, the rest of the page is only what helps you start a run from here. The options are one chip away, AFK is one line, an issue is something you act on, and status appears only when it blocks you.

Model and effort: one chip, two taps

  • The composer bar holds chips again, as today: Model, Effort, and a ⋯ for the rest (agent, remote control, label, the Runner note). The row scrolls sideways on a phone instead of wrapping, so the send stays pinned and the field keeps one height.
  • Tapping Model opens a picker right away: a bottom sheet on the phone, a popover on the chip on desktop. Pick → done. Two taps, never three. A chip that differs from the inherited default is outlined in the accent, so a per-spawn pick is visible.
  • Catalog for Claude Code: Fable 5.1, Opus 5.5, Sonnet 5.5. No Haiku. The inherited default is marked in the list.

Repository

  • The pills are the recent repositories, one tap each. "All" now opens the repository picker, not the Repositories page.
  • The picker starts with a search field that filters as you type (name or host), Recent first, then All. Enter picks the first match. This is the existing Select component's filter input, so the implementation already exists.

Issues, with an action

  • The Issues card lists the repo's open issues with their triage label, newest first. Not only the claimable ones: a needs-triage issue is as much a reason to start a run as a ready one.
  • Tapping an issue asks what the agent should do with it. Triage starts a run whose first message is /triage #47: the repo's triage skill reads the issue, asks you what is missing, and sets the label. Implement seeds a manual run with the issue as its brief, on its own branch. Discuss opens a chat with the issue as context and waits for you. The suggested action follows the label.
  • The chosen action attaches to the composer; anything you type is added to it. Send starts the run.
  • None of this needs a server change: the action is the run's first message, which the spawn already carries (issue #96). The AFK seed prompt is untouched.

Nothing here leaves the page

  • Recent prompts are gone.
  • "All N open issues" opens the full list in place: a text filter by number or title, then chips that narrow by state (needs-triage, ready-for-agent, needs-info, unlabeled) with counts, then the rows. The search stays pinned while the rows scroll. At 50 or 200 issues this is two taps to the needs-triage ones; the state "50 open issues" shows it at that size. Picking one goes straight to the action sheet.
  • The list is the tracker's open issues as lab last read them (bounded reads, ADR-0050), the same list the Issues tab shows, so the card and the picker add no forge request of their own when that list is fresh.
  • The readiness line is gone. A repo that can run shows nothing about it: the enabled composer is the signal, and the pill's dot already carries the repo's state. Only a blocker appears, and it appears at the composer: a cloning repo, a failed clone, a logged-out agent (the field is disabled, with Reconnect), or a failing tracker (a warning with Fix, because a manual run can still start). The full six-check report stays on the repo home, where you go to check a repo.

AFK is one line

  • "Auto on · 3 ready · 1 AFK run live" with the Auto switch in the card head. Run one appears only when Auto is off, since with Auto on the engine claims the next issue itself. A paused repo shows Reset here.

Still open

  • Typing # in the composer could offer the same issue autocomplete inline; left out of this round.
  • Whether Implement should instead claim the issue through the AFK machinery (own branch pattern, done-signal, three-strikes). As drawn it is a manual run with a seeded brief.

States: model, repo, issues, many, more, action, triage, implement, autooff, codex, loggedout; add .desktop for the desktop frame. Sample content is invented; issue titles are the repo's real open issues. Markup here is throwaway; follow the app's components and tokens when implementing.
